# snapreel

Скриншот, но видео. Жмёте хоткей, выделяете мышью кусок экрана, он пишется
от 5 до 60 секунд — и готовый файл оказывается **в буфере обмена**. Дальше
обычный Ctrl+V в Telegram, Slack, браузер или чат агента.

Windows, macOS, Linux. Python + ffmpeg, без тяжёлых зависимостей.

## Как это работает

```
хоткей → оверлей выделения → ffmpeg пишет область → MP4 (или GIF)
       → файл в буфер обмена + копия в ~/Videos/Snapreel
```

В буфер кладётся **сам файл**, а не картинка и не путь: на Windows это формат
`CF_HDROP` — тот же, которым проводник копирует файлы по Ctrl+C. Поэтому
вставка работает везде, где принимают перетаскивание файлов.

## Установка

### Готовый бинарник

На [странице релизов](https://github.com/elementary1997/snapreel/releases)
лежит одиночный исполняемый файл под Linux, macOS (Intel и Apple Silicon) и
Windows. **Ставить ничего не нужно**: ffmpeg вшит внутрь, Python не нужен —
скачали, запустили, выделяете область.

При первом запуске откроется окно настроек: назначьте горячую клавишу —
её не печатают, а нажимают, — и всё остальное там же. Дальше двойной щелчок
сразу начинает запись, а вернуться к настройкам можно в любой момент:

```bash
./snapreel settings
```

На Linux дополнительно нужны системные утилиты буфера обмена (`xclip` в X11,
`wl-clipboard` в Wayland) — вшить их нельзя, `setup` покажет команду.

На macOS бинарник не подписан, поэтому при первом запуске снимите карантин:
`xattr -d com.apple.quarantine ./snapreel-macos-*`.

Вшитый ffmpeg собран из исходников только с нужным snapreel — захват экрана,
H.264, MP4 и GIF, — поэтому весит около шести мегабайт, а не сто сорок. Он под
GPL: версии, адреса исходников и флаги сборки — в
[THIRD_PARTY_LICENSES.md](THIRD_PARTY_LICENSES.md).

### Из исходников

Нужен только Python 3.11+. Остальное — ffmpeg, tkinter, утилиты буфера обмена —
доставит сам установщик (при установке из исходников ffmpeg берётся системный,
вшивают его только в релизные бинарники).

**Linux и macOS:**

```bash
cd snapreel
./scripts/install.sh
```

**Windows** (PowerShell):

```powershell
cd snapreel
.\scripts\install.ps1
```

Скрипт создаёт venv, ставит пакет, доустанавливает системные зависимости через
пакетный менеджер (apt / dnf / pacman / zypper / brew / winget), **спрашивает
вашу комбинацию клавиш**, назначает её в системе и прогоняет проверку.

Без вопросов:

```bash
./scripts/install.sh --hotkey 'Ctrl+Alt+5' --yes
```

Если предпочитаете ставить руками:

```bash
pip install -e '.[daemon]'
snapreel setup      # зависимости + хоткей
snapreel doctor     # что не так
```

`setup` ничего не ставит молча: он показывает список недостающего и точные
команды пакетного менеджера, и лишь потом спрашивает разрешение.

## Использование

```bash
snapreel record              # выделить область и записать MP4
snapreel record --gif        # то же, но в буфер уйдёт GIF
snapreel record --seconds 15 # ограничить длительность
snapreel record --region 800x600+100+100   # без выделения мышью
snapreel doctor              # диагностика окружения
snapreel prune               # убрать клипы старше keep_days
```

Во время записи видна красная рамка вокруг области и таймер с кнопкой «Стоп».
Остановиться можно по Esc или кнопкой — но не раньше `min_seconds`. По
достижении `max_seconds` запись закрывается сама.

## Настройки

Всё настраивается в окне: `snapreel settings`. Оно же открывается при первом
запуске. Горячие клавиши, длительность и качество, каталог клипов, GIF, звук,
срок хранения — правка TOML руками больше не нужна нигде.

Терминал по-прежнему умеет то же самое, если так привычнее.

## Обновление

snapreel сам скажет, когда выйдет новая версия, и поставит её по кнопке в
окне настроек. Из терминала:

```bash
snapreel update           # проверить и поставить
snapreel update --check   # только посмотреть
```

Скачанный файл сверяется с `SHA256SUMS` из того же релиза, и без этой сверки
установка отменяется. Проверка идёт **раз в сутки** и отключается
переключателем в настройках (`check_updates`).

Это единственное место, где snapreel выходит в сеть: анонимный запрос к
github за списком релизов. Наружу не уходит ничего — ни версия, ни
идентификаторы, ни статистика, ни тем более записанное видео (ADR-0007).

## Хоткей — какой захотите

Комбинацию выбираете вы, на любой системе:

```bash
snapreel hotkey set 'Ctrl+Alt+5'      # назначить и сохранить
snapreel hotkey set                   # спросит интерактивно
snapreel hotkey set --gif 'Ctrl+Alt+6'
snapreel hotkey show                  # что назначено сейчас
snapreel hotkey remove                # снять
```

Синтаксис свободный: `Ctrl+Alt+5`, `Win+Shift+S`, `alt+f9`, `<ctrl>+<shift>+r` —
всё разбирается одинаково. Модификатор обязателен, иначе клавиша перестанет
печататься, и snapreel об этом скажет вместо того, чтобы сломать вам клавиатуру.

Куда прописывается комбинация:

| ОС | механизм | автоматически |
|---|---|---|
| GNOME | своя комбинация в media-keys (`gsettings`) | да |
| Windows | ярлык в меню «Пуск» со свойством Hotkey | да |
| KDE, i3, Sway, прочие | своя система горячих клавиш | нет — команда печатается, привязать вручную |
| macOS | Automator + Службы, либо демон | нет — инструкция печатается |

Где автоматически не выходит, `setup` печатает готовую команду вида
`/путь/python -m snapreel record` — остаётся привязать её штатными средствами
окружения.

### Демон как запасной вариант

```bash
snapreel daemon      # слушает обе комбинации, MP4 и GIF
snapreel autostart   # macOS: демон в автозапуск (LaunchAgent)
```

Демон работает на Windows, X11 и macOS (последней нужно разрешение
«Универсальный доступ»). **В Wayland он не заработает** — композитор не отдаёт
глобальные клавиши, там только системный хоткей.

## Конфигурация

`snapreel config` печатает файл со всеми значениями по умолчанию. Класть сюда:

- Linux/macOS: `~/.config/snapreel/config.toml`
- Windows: `%APPDATA%\snapreel\config.toml`

Основное:

| ключ | по умолчанию | смысл |
|---|---|---|
| `fps` | 30 | частота кадров |
| `min_seconds` / `max_seconds` | 5 / 60 | границы длительности |
| `crf` / `preset` | 23 / veryfast | качество и скорость H.264 |
| `gif_fps` / `gif_max_width` | 15 / 900 | параметры GIF (только уменьшение) |
| `output_dir` | `~/Videos/Snapreel` | куда складывать клипы |
| `keep_days` | 30 | через сколько дней удалять старое, 0 — не трогать |
| `hotkey_mp4` / `hotkey_gif` | Ctrl+Shift+Alt+R / …+G | комбинации, меняются через `hotkey set` |
| `copy_path_as_text` | false | класть в буфер путь вместо файла |
| `capture_audio` / `audio_device` | false / "" | запись звука |
| `check_updates` | true | раз в сутки спрашивать github о новой версии |

Любой ключ перекрывается переменной окружения: `SNAPREEL_FPS=60 snapreel record`.

## Про вставку в чаты агентов

MP4 вставится как вложение, но **модели не смотрят видео** — LLM-чаты обычно
принимают только изображения. Если нужно, чтобы агент действительно увидел
происходящее, берите `--gif`: анимированный GIF многие интерфейсы разбирают
как картинку. Гарантии одинаковой обработки нет, это зависит от конкретного
чата.

## Ограничения

- **WSL**: изнутри WSL виден только экран WSLg, а не рабочий стол Windows.
  Ставьте snapreel на хост. Записать сам WSLg можно через `SNAPREEL_ALLOW_WSL=1`.
- **Wayland**: используется `wf-recorder`, то есть композиторы на wlroots
  (Sway, Hyprland, river). GNOME и KDE со своими протоколами записи не
  поддержаны — там остаётся сессия X11.
- **macOS с несколькими мониторами**: запись идёт с одного экрана
  (`screen_index` в конфиге), область за его пределами не попадёт в кадр.
- **Linux X11**: `xclip` отдаёт буфер, пока жив его процесс. Он остаётся в
  фоне после записи — это нормально и так же работает у остальных утилит.

## Разработка

```bash
make setup    # .venv и пакет с dev-экстрой
make check    # линт + тесты, то же гоняет CI
make build    # одиночный бинарник в dist/
make doctor   # диагностика этой машины
make help     # все команды
```

Релиз собирается по тегу `v*`: workflow `release.yml` строит бинарники на
четырёх платформах, проверяет каждый запуском и выкладывает в GitHub Release
вместе с `SHA256SUMS`.

Тесты не трогают экран: проверяются сборка команд ffmpeg для всех четырёх
бэкендов, разбор и нормализация хоткеев, команды пакетных менеджеров,
геометрия, конфиг и хранилище. CI прогоняет их на Linux, macOS и Windows,
плюс отдельная сквозная запись на виртуальном экране Xvfb.

Окно настроек проверяется отдельно — ему нужен настоящий дисплей:

```bash
xvfb-run pytest -m gui
```

В обычный прогон эти тесты не входят (на живом оконном менеджере они виснут
на захвате фокуса), но в CI их гоняет тот же job, что и сквозную запись.

границы модулей и список граблей. Архитектура — [docs/architecture.md](docs/architecture.md),
принятые решения и их причины — [docs/adr/INDEX.md](docs/adr/INDEX.md).
