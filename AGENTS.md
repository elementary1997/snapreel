# Project: snapreel

Настольная утилита: по горячей клавише пользователь выделяет мышью область
экрана, она пишется в видео 5–60 секунд, и готовый файл кладётся в буфер
обмена для вставки по Ctrl+V. Работает на Windows, macOS и Linux (X11 и
Wayland). Запускается как CLI на машине пользователя; сервера нет.

## Dev environment

- Python 3.10+ (используются `match`-совместимые аннотации `X | None` и `tomllib`).
- Виртуальное окружение — `.venv` в корне; создаётся `make setup`.
- Пакетный менеджер: `pip` с `-e`. НЕ используй poetry, uv или conda — сборка на hatchling.
- Внешняя зависимость: `ffmpeg` и `ffprobe` в `PATH`. В Linux дополнительно
  `xclip` (X11) или `wl-clipboard` + `wf-recorder` (Wayland), плюс `python3-tk`.
- Python-зависимостей в рантайме нет вообще. `pynput` — только для `snapreel daemon`,
  ставится экстрой `.[daemon]`. Не добавляй зависимости без ADR.

## Build & test

- `make setup` — создать `.venv` и поставить пакет с dev-экстрой.
- `make test` — pytest (быстро, экран не нужен).
- `make lint` — ruff (проверка + формат); `make format` чинит автоматически.
- `make check` — lint + test; это же гоняет CI.
- `make doctor` — диагностика окружения текущей машины.
- `make build` — одиночный бинарник PyInstaller в `dist/`.
- `make clean` — убрать `.venv`, кэши и артефакты сборки.

Тесты обязаны проходить в headless-окружении: без дисплея, без ffmpeg,
без буфера обмена. Всё внешнее подменяется.

## Architecture overview

Одиночный пакет `src/snapreel`, слоями:

- `cli.py` — разбор аргументов, ввод-вывод пользователя. Единственное место с `print`/`input`.
- `recorder.py` — оркестрация сценария: выделить → записать → упаковать → в буфер.
- `backends/` — четыре реализации захвата, по одной на платформу; общий контракт в `base.py`.
- `clipboard/` — три реализации буфера обмена; диспетчер в `__init__.py`.
- `selector.py` / `indicator.py` — Tk-оверлеи (выделение области и рамка записи).
- `platform_info.py`, `region.py`, `config.py`, `storage.py`, `deps.py`, `autostart.py` — без побочных эффектов, легко тестируются.

Подробности и диаграммы — `docs/architecture.md`, принятые решения — `docs/adr/INDEX.md`.

## Conventions & patterns

- **Комментарии и docstrings — по-русски**, имена и код — по-английски. Так уже написан весь пакет.
- Docstring объясняет **почему**, а не пересказывает сигнатуру. Если нечего сказать сверх имени — не пиши docstring.
- Новая платформа добавляется классом-наследником `CaptureBackend`, а не `if platform ==` в общем коде.
- Определение платформы живёт только в `platform_info.detect()`. НЕ вызывай `sys.platform`/`platform.system()` в других модулях.
- Модули, специфичные для одной ОС, импортируются **лениво**, внутри функции. `clipboard/windows.py` тянет `ctypes.wintypes` и на Linux падает при импорте; `tkinter` есть не в каждой сборке Python.
- Ошибки наружу — своими типами (`CaptureError`, `RegionError`, `ClipboardError`, `HotkeySetupError`, `SelectionCancelled`), а не голыми `RuntimeError`.
- Сообщения об ошибках пишутся для пользователя: что не так **и что с этим делать**. Пример: «не найден wl-copy — установите wl-clipboard».
- Сбой второстепенного шага (буфер, уведомление, prune) НЕ должен терять уже записанный клип.
- Команды ffmpeg собираются чистыми функциями `build_command()` и покрываются тестами без запуска ffmpeg.
- Тесты пишутся на поведение и называются предложением: `test_clipboard_failure_keeps_the_clip`.

## Security

- Секретов в проекте нет и быть не должно: приложение локальное, сети не делает.
- `deps.py` умеет запускать `sudo apt-get install` и подобное. Любая установка выполняется **только после явного подтверждения** пользователя (`--yes` или ответ в терминале). Не расширяй этот список без нужды и не добавляй автозапуск без подтверждения.
- `autostart.py` пишет в системные места (реестр ярлыков Windows, gsettings, LaunchAgents). Меняй осторожно и всегда оставляй обратную операцию (`hotkey remove`).
- Записанное видео — чувствительные данные пользователя. Не логируй содержимое, не отправляй никуда, не добавляй телеметрию.

## Gotchas

Это не догадки — на всём перечисленном уже наступали.

- **WSL не видит экран Windows.** Изнутри WSL доступен только дисплей WSLg. Запись экрана хоста оттуда невозможна; `backends.for_environment` намеренно бросает ошибку, обход — `SNAPREEL_ALLOW_WSL=1`. Не «чини» это.
- **Стороны кадра обязаны быть чётными.** `libx264` + `yuv420p` не берёт нечётную ширину или высоту. За это отвечает `region.normalize()`; на macOS то же самое повторяется после умножения на масштаб Retina.
- **Отрицательные координаты — норма.** Монитор слева от основного даёт `x < 0`. Не «санируй» их в ноль.
- **DPI на Windows.** `platform_info.enable_dpi_awareness()` обязан вызываться до создания первого окна Tk, иначе при масштабе 125% Tk отдаёт логические координаты, а gdigrab снимает физические — запишется не та область.
- **Retina на macOS.** avfoundation отдаёт физические пиксели, Tk — логические точки. Масштаб измеряется пробным кадром и кешируется в `~/Library/Caches/snapreel/probe.json`.
- **Останов ffmpeg — буква `q` в stdin, не сигнал.** На Windows SIGINT до дочернего процесса нормально не доходит, а `terminate()` оставляет битый контейнер. Исключение — `wf-recorder`, он останавливается по SIGINT (`graceful_stop = "sigint"`).
- **У `wf-recorder` нет ограничения по времени.** Лимит `max_seconds` держит таймер в `RecordingIndicator`, а не аргумент команды.
- **`xclip` держит буфер, пока жив его процесс.** Поэтому он запускается с `start_new_session=True` и переживает выход snapreel. Так работает X11, это не утечка.
- **GIF масштабируется только вниз.** В фильтре стоит `scale=w='min(gif_max_width,iw)'`; простое `scale=900:-1` растягивало узкие клипы.
- **`snapreel doctor` обязан работать при сломанном окружении** — без tkinter, без ffmpeg, в WSL. Поэтому GUI-модули импортируются лениво, а `errors.py` не тянет tkinter.
- **`prune` удаляет только свои файлы.** Каталогом вывода пользователь вправе назначить общий `~/Videos`, поэтому удаляется лишь то, чьё имя узнал `naming.pattern`. Не упрощай до «все `*.mp4` в каталоге» — это стоило бы человеку домашнего архива.
- **`filename_template` — не произвольный strftime.** Допустимы только директивы из `naming.DIRECTIVES` и простые литералы; остальное отвергается при загрузке конфига. Причина в том, что множество директив strftime не перечислимо: неизвестная директива в выражении либо совпадёт с чем угодно и унесёт чужие файлы, либо не совпадёт ни с чем и `keep_days` молча перестанет работать. Расширять карту можно, ослаблять грамматику — нет.
- **Из `to_gif` наружу выходит только `EncodeError`.** Таймаут, отсутствующий бинарь, любой сбой запуска — всё заворачивается: выше по стеку уже лежит записанный клип, и терять его из-за подробностей внешнего процесса нельзя.
- **Значение из конфига не роняет команду.** `doctor` и `hotkey show` показывают испорченный хоткей строкой (`autostart.describe_safe`) и добавляют его в список проблем, а не падают трейсбеком.
- **В собранном бинарнике нет модуля `snapreel` для интерпретатора.** `sys.executable` там указывает на сам бинарник, поэтому команда хоткея строится как `snapreel record`, а не `python -m snapreel record` — за это отвечает `autostart.is_frozen()` — то же касается `daemon_argv()` и plist для LaunchAgent.
- **Индикатор записи сам не попадает в кадр**: рамка собрана из четырёх окон по краям области, а не из одного окна поверх неё.
