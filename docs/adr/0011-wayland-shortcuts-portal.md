# 11. Горячие клавиши Wayland через GlobalShortcuts

Дата: 2026-10-03

## Status

Accepted.

## Context

Отказ от перехвата клавиатуры в Wayland не означает отсутствия горячих
клавиш. KDE Plasma предоставляет портал GlobalShortcuts: рабочий стол
спрашивает разрешение и отдаёт приложению только зарегистрированные действия.
Безусловный отказ в `hotkeys.why_silent` не давал использовать эту возможность.

## Decision

В настоящей сессии Wayland (кроме WSLg) используем интерфейс
`org.freedesktop.portal.GlobalShortcuts`. Регистрируем две независимые
комбинации MP4 и GIF в одной сессии. Предпочтительные сочетания берём из
конфига; окончательный выбор остаётся у пользователя в системном диалоге.

D-Bus обслуживает системная библиотека GIO через ctypes. Новых Python-пакетов
нет. Библиотеки `libgio-2.0.so.0`, `libglib-2.0.so.0` и `libgobject-2.0.so.0`
нужны только этому пути; отсутствие оформляется собственной ошибкой с советом.
GIO работает в отдельном GLib-контексте потока. Обработчики трея передают
действия в главный поток уже существующим механизмом Qt.

Подписка на Response устанавливается до запроса с уникальным handle_token,
чтобы не потерять быстрый ответ. При отказе, частичном разрешении и остановке
слушателя сессия закрывается, подписки и ссылки освобождаются. `doctor` только
проверяет наличие интерфейса, не запрашивая разрешения и не открывая окна.

## Consequences

- X11, Windows, macOS и WSLg сохраняют прежний механизм.
- В KDE нужны xdg-desktop-portal и xdg-desktop-portal-kde с поддержкой
  GlobalShortcuts. Если интерфейса нет, показываем инструкции по установке
  или ручному назначению системных хоткеев.
- Сочетания из конфига — предпочтения для портала; рабочий стол вправе
  сохранить уже выбранные пользователем сочетания.
- Захват экрана KDE/GNOME через ScreenCast и PipeWire описан отдельно в ADR-0012.
