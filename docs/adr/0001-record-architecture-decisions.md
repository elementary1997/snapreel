# ADR-0001: Вести журнал архитектурных решений

## Status

Accepted (2026-09-05)

## Context

snapreel почти целиком состоит из решений, которые в коде выглядят
произвольными: почему в буфер кладётся файл, а не картинка; почему ffmpeg
запускается процессом, а не через биндинги; почему останов идёт буквой `q`
в stdin. Причины таких выборов из кода не видны.

Проект пишется в паре с AI-агентами. Агент, не знающий причины, при первом же
«улучшающем» рефакторинге предложит откатить решение к более частотному
паттерну из обучающей выборки — например, заменить `q` на `terminate()`.

## Decision

Ведём ADR в `docs/adr/` в формате Nygard: `NNNN-kebab-case.md` со статусом,
контекстом, решением, последствиями и рассмотренными альтернативами.
Каталог — `docs/adr/INDEX.md`, ссылка на него стоит в `AGENTS.md`.

ADR заводится на решение, которое: влияет на структуру или зависимости,
трудно обратимо, либо выглядит странно без объяснения.

## Consequences

+ Агент и человек видят «почему», а не только «как».
+ Отвергнутые варианты зафиксированы и не предлагаются повторно.
- Каждое заметное решение требует нескольких минут на запись.
~ Существующие ADR не переписываются и не удаляются: только `Superseded by`.

## Alternatives considered

- **Комментарии в коде** — не отвечают на «какие варианты отвергли и почему»,
  и теряются при рефакторинге. Оставлены для локальных пояснений.
- **Раздел в README** — README читают пользователи, а не контрибьюторы;
  решения там утонут.
- **Вики на GitHub** — живёт отдельно от кода, разъезжается с ним и не
  попадает в контекст агента при клоне репозитория.
