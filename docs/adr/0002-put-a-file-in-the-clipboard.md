# ADR-0002: Класть в буфер обмена файл, а не изображение

## Status

Accepted (2026-09-05)

## Context

Смысл snapreel — вставить записанный клип по Ctrl+V так же просто, как
вставляют скриншот. Но «видео» как тип данных буфер обмена не поддерживает
ни в одной из трёх целевых ОС:

- Windows: буфер знает `CF_BITMAP`, `CF_DIB`, `CF_HDROP` (список файлов).
  Анимации в растровых форматах нет — GIF, положенный как изображение,
  теряет все кадры кроме первого.
- macOS: pasteboard принимает `public.file-url` либо статические картинки.
- Linux: X11 и Wayland оперируют MIME-типами; для файлов принято `text/uri-list`.

## Decision

Кладём в буфер **сам файл** тем механизмом, которым это делает файловый
менеджер при Ctrl+C:

- Windows — `CF_HDROP` плюс `Preferred DropEffect = Copy`, на голом `ctypes`.
- macOS — `osascript` с `POSIX file`.
- Wayland — `wl-copy --type text/uri-list`.
- X11 — `xclip -t text/uri-list`.

Копия всегда сохраняется на диск (`~/Videos/Snapreel`), потому что все эти
механизмы ссылаются на файл, а не переносят его содержимое.

## Consequences

+ Ctrl+V работает везде, где принимают перетаскивание файлов: Telegram, Slack,
  Discord, браузеры, файловые менеджеры, поля загрузки на веб-страницах.
+ Не нужен pywin32: `CF_HDROP` собирается через `ctypes` вручную.
- Файл обязан пережить вставку, поэтому клипы копятся на диске; за это отвечает
  `keep_days` и `snapreel prune`.
- В X11 буфер живёт, пока жив процесс `xclip`, — он намеренно запускается
  отсоединённым и переживает выход snapreel.
- Приложения, принимающие только растровые данные (простые графические
  редакторы), вставку не поймут. Это осознанный компромисс.

## Alternatives considered

- **Класть первый кадр как изображение** — теряет саму суть инструмента.
- **Класть путь текстом** — оставлено как опция `copy_path_as_text`, но плохо
  как поведение по умолчанию: в чат вместо видео улетит строка.
- **Регистрировать свой формат буфера** — его никто не читает.
- **Загружать клип на хостинг и класть ссылку** — требует сети, аккаунта и
  утечки приватного содержимого экрана наружу. Отвергнуто.
