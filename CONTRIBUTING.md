# Как участвовать

## Быстрый старт

```bash
make setup    # .venv + пакет с dev-экстрой
make check    # линт и тесты — то же, что в CI
```

Работаете с AI-агентом? Он должен сначала прочитать [AGENTS.md](AGENTS.md) —
там конвенции, границы модулей и список граблей, на которые уже наступали.

## Что важно знать до первого PR

- **Тесты не трогают экран.** Ни дисплея, ни ffmpeg, ни буфера обмена в тестах
  быть не должно: команды ffmpeg проверяются сравнением аргументов, всё
  внешнее подменяется. Иначе CI на macOS и Windows развалится.
- **Платформенный код — в бэкендах.** Новая ОС или способ захвата — это новый
  класс-наследник `CaptureBackend`, а не ветвление в общем коде.
- **Комментарии по-русски, код по-английски.** Так написан весь пакет.
- **Заметное решение — в ADR.** Формат и критерии — `docs/adr/INDEX.md`.

## Коммиты и ветки

- Ветка: `feature/<слаг>` или `fix/<слаг>`.
- Коммиты — Conventional Commits, заголовок на английском:
  `feat: add wayland portal backend`.
- `make check` зелёный до пуша.

## Правила для агентов

`CLAUDE.md` и `.github/copilot-instructions.md` — **сгенерированные копии**
`AGENTS.md`. Правьте только `AGENTS.md`, затем:

```bash
make sync-agent-rules
```

## Проверить руками

Автотесты не покрывают то, ради чего всё затевалось — реальную запись экрана
и вставку из буфера. Перед релизом стоит пройти вручную на своей платформе:

1. `snapreel record` — выделение, рамка, таймер, кнопка «Стоп».
2. Ctrl+V в мессенджер — вставился ли именно файл.
3. `snapreel record --gif` — GIF не растянут и не «грязный».
4. `snapreel doctor` — честно ли перечисляет недостающее.
